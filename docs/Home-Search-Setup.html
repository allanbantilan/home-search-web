01 · Local setup

Run the WordPress demo

Requirements: Docker Desktop running on Windows, PowerShell 7, and an unused localhost port. Open a terminal in the project folder:

cd C:\projects\wp-web\real-estate-smart-search
pwsh -NoProfile -File .\setup-local.ps1 -SeedDemo

Open http://127.0.0.1:57106/. The script prints a randomly generated admin password on the first install; save it privately. The admin dashboard is at /wp-admin/. If port 57106 is busy, choose another port and project name:

pwsh -NoProfile -File .\setup-local.ps1 -Port 57107 `
  -Project home-search-demo-2 -SeedDemo

The script is safe to rerun: it keeps the Docker volumes and existing content. It starts MariaDB and WordPress, installs the WordPress database if needed, installs ACF, activates the Estate Search plugin and Home Search theme, enables pretty permalinks, and optionally seeds three listings and one agent. The theme creates Contact, Compare, and Saved Homes pages when activated.

Local use only. The .docker-test/compose.yml file contains example database passwords and a mail-capture plugin. It is deliberately bound to 127.0.0.1. Do not copy it to a public VPS.

Verify the installation

node tests/site.test.cjs
node --check property-search/assets/js/site.js
python tests/integration.py http://127.0.0.1:57106
python tests/browser.py http://127.0.0.1:57106

Browser checks require Python Playwright and a local Chrome installation. The integration test sends sample contact and viewing requests; the local mail-capture plugin prevents external delivery.

To stop the demo without deleting data: docker compose -p home-search-local -f .docker-test/compose.yml down. Never add -v unless you intend to erase its database and uploads.

02 · WordPress content

Configure the real site

  1. Install the two project folders. Copy estate-search to wp-content/plugins/ and property-search to wp-content/themes/. Activate Estate Search, install and activate Advanced Custom Fields, then activate the Home Search theme.
  2. Set permalinks. In Settings → Permalinks, choose “Post name” and save. Confirm /properties/ and /agents/ work.
  3. Create agents first. Add each agent under Agents with a valid email, role, phone, biography, and portrait. Viewing requests use the assigned agent’s email.
  4. Add properties. Include title, description, price, location, address, bedrooms, bathrooms, area, property type, coordinates, featured photo, and assigned agent. Use a WordPress Gallery block in the description for additional images.
  5. Set office contact details. The general contact form sends to the WordPress administration email in Settings → General. Replace demo people, addresses, and example.test emails before publication.
  6. Configure mail. Install FluentSMTP, connect a verified sending domain and mail provider, then send a test email. Submit both the contact form and a property viewing request and confirm the office and assigned agent receive them.

Plugin choices

RequiredAdvanced Custom Fields — edits property and agent fields registered by Estate Search.
RecommendedFluentSMTP — authenticated delivery for wp_mail(). Configure one mail plugin only.
OptionalFluent Forms only if office staff must change form fields or notification rules. The included forms already route leads.

The payment calculator estimates principal and interest only. It excludes insurance, taxes, fees, and lender adjustments. Favorites and comparisons are stored in each visitor’s browser.

03 · VPS launch

Deployment sequence

Use a maintained WordPress host stack on the VPS: a supported WordPress/PHP release, MariaDB or MySQL, persistent database and uploads, and an HTTPS reverse proxy. The local Docker Compose file is a test fixture, not a production manifest.

  1. Prepare infrastructure. Point the domain’s DNS to the VPS. Apply operating-system updates, restrict SSH, and allow only required public ports. Keep the database inaccessible from the public internet.
  2. Install WordPress with HTTPS. Configure the site URL as https://your-domain.example, issue and renew a TLS certificate, and check secure admin login and pretty permalinks. Use strong, unique database and administrator credentials.
  3. Install this project. Add the two folders and the required ACF plugin as described on page 3. Import production property content and media; do not publish the local sample agent or test addresses.
  4. Enable delivery. Configure FluentSMTP with the real sender domain, SPF/DKIM/DMARC where supported, and verify delivery to both office and agent inboxes. The local mail-capture plugin must not be present.
  5. Set map service. The theme uses Leaflet with public OpenStreetMap tiles. Review the tile usage policy; use a dedicated tile provider when traffic or service needs exceed it.
  6. Protect and operate. Schedule offsite backups of the database and uploaded media, test a restore, keep WordPress/plugins/PHP updated, monitor errors and disk space, and publish an appropriate privacy notice for enquiry data.
VPS verdict: The theme and plugin passed local functional tests and can be installed on a VPS. A public launch is not ready until HTTPS, real mail delivery, backups with a tested restore, production content, and live-server checks are complete.

A VPS was not supplied for this review, so no DNS, TLS, mail provider, firewall, backup restore, or production load test was performed.

What was tested

Search and mapPass — live filters, REST response, invalid range handling, map marker.
Visitor actionsPass — favorites, compare, payment estimate, contact and viewing forms, invalid nonce rejection.
Chrome reviewPass — homepage rendered with no console errors; desktop and mobile checked.

Final launch gate

  • Confirm the public domain, HTTPS certificate, and admin login.
  • Verify real email delivery to the office and at least two assigned agents.
  • Run a backup and restore it to a separate test instance.
  • Check mobile and desktop pages, broken links, map tiles, and browser console on the public URL.
  • Review production photos, prices, agent details, legal copy, privacy notice, and calculator disclaimer.
